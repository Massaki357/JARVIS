## Arquitetura e decisões de design

- `jarvis/pacotes/delegacao_ia/` — delegates one-off text tasks to a faster/cheaper/more-capable LLM provider than doing it inline in the Live session, for cases where that trade-off is worth an extra call. Same package contract as the others (`obter_function_declarations()`/`despachar()`, no session-glue wiring — see docs/INTEGRATION.md), exposed as a single tool `delegar_tarefa(tipo_tarefa, conteudo)` rather than one tool per provider, so the model (not a separate classification call) picks the task type from conversation context. `roteador.py` splits into two paths, deliberately asymmetric because OpenAI is the most expensive provider in use and is meant to be called rarely:
     - `pergunta_rapida`→Groq and `resumo`→Cerebras go through the generic path (`MAPA_PROVEDOR_PRINCIPAL`/`MAPA_PROVEDOR_FALLBACK`): each has a one-shot fallback to the other cheap/fast provider, and if both fail, `delegar()` returns `MENSAGEM_INDISPONIVEL` — an instruction for the model to just answer itself, failure unmentioned to the user (deliberately baked into the returned tool-result text, not left to system-prompt discipline alone).
     - `segunda_opiniao`→OpenAI is handled separately by `_delegar_segunda_opiniao()`, on purpose with **no fallback** to Groq/Cerebras (falling back would defeat the point of an *independent* second AI) and a **distinct failure message** (`MENSAGEM_SEGUNDA_OPINIAO_INDISPONIVEL`) that explicitly instructs the model to tell the user it couldn't get a second opinion this time, unlike the silent-failure behavior of the generic path. On success, the OpenAI response is wrapped (not returned raw) with an instruction telling the model to compare it against its own reasoning and synthesize both viewpoints rather than relay it verbatim. `instrucao_sistema` in `jarvis/cerebro/gemini/cliente_live.py` (# DELEGAÇÃO DE TAREFAS section) spells out the pergunta-normal-vs-segunda_opiniao distinction with concrete examples (financial/high-stakes decisions → `segunda_opiniao`; direct-knowledge or no-real-risk reasoning tasks like explaining a concept or comparing two technologies → answer directly, no delegation at all). There used to be a third type, `raciocinio_complexo`→OpenAI — removed entirely; that kind of reasoning is now expected to be handled by Gemini itself rather than delegated by default.
     - `provedores.py` is a single generic OpenAI-compatible-schema HTTP helper (`requests`, no per-provider SDK) reused for all three providers, since Groq/Cerebras/OpenAI all expose the same `POST .../chat/completions` shape; each provider function returns `(sucesso, resultado_ou_erro)`, never raises. **Model names are a moving target** — the ones hardcoded as defaults in `config.py` (`MODELO_GROQ`/`MODELO_CEREBRAS`/`MODELO_OPENAI`, each overridable via its own env var) were confirmed live against each provider's real `/v1/models` endpoint while writing this, not from general knowledge — Groq/Cerebras in particular had already dropped every Llama-branded chat model that used to be the obvious default, in favor of `gpt-oss`/`qwen`/`gemma` families. If a provider call starts failing with a `model_not_found`-shaped error, re-check that endpoint live rather than guessing a replacement name from memory.
