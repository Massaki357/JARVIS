# jarvis/pacotes/fechar_app/

> Contexto detalhado deste módulo, extraído do CLAUDE.md raiz. Leia antes de editar arquivos desta área.

## Arquitetura e decisões de design

- `jarvis/pacotes/fechar_app/` — closes an already-running app by spoken name (`fechar_app(nome_falado)`). Same isolated-package contract as the others (`obter_function_declarations()`/`despachar()` — see docs/INTEGRATION.md). Name resolution (`processos.py`) copies the project's usual name-matching technique (accent/case fold, substring, `difflib` cutoff 0.72) rather than importing it, matching this project's per-package duplication convention.
     - **Graceful before forced, always.** `fechador.py` first sends `WM_CLOSE` (via `win32gui.PostMessage`, never `SendMessage`, so a slow/unresponsive app can't block the caller) to every visible, titled top-level window belonging to the resolved process's PID(s) — found via `win32gui.EnumWindows` + `win32process.GetWindowThreadProcessId`. It waits up to `TIMEOUT_FECHAMENTO_GRACIOSO_SEGUNDOS` (5s) for the process to actually exit, giving the app itself a chance to show its own "save before closing?" prompt. Only a process with no visible window at all, or one that doesn't exit within that window, gets `terminate()` and then `kill()` (both effectively `TerminateProcess` on Windows — there's no separate SIGKILL to distinguish, so both are called as belt-and-suspenders exactly as requested).
     - **Protected-process list is a hard block, checked before touching anything.** `PROCESSOS_PROTEGIDOS` (`explorer.exe`, `winlogon.exe`, `csrss.exe`, `services.exe`, `svchost.exe`) is checked by exact, case-insensitive name match — never a prefix/substring match that could be tricked. The ALFRED process itself is protected separately, by **PID** (`os.getpid()`), not by process name — blocking "python.exe"/"pythonw.exe" generically would also refuse to close any unrelated Python process the user happens to be running, which isn't the intent.
     - **Multiple processes sharing the resolved name are all closed together** (e.g. several windows/processes of the same browser), with the final message reporting how many closed gracefully vs. how many were forced — never silently picks just one.
     - Verified live: closing a real running app (graceful path taken, confirmed via the process actually exiting before the forced-close branch ever ran); attempting to close `explorer.exe` (correctly refused, no attempt made at all — not even the graceful WM_CLOSE); closing an app with multiple open windows (all closed, count reported correctly).

## Restrições a preservar ao editar

- `fechar_app`'s `PROCESSOS_PROTEGIDOS` list (`explorer.exe`, `winlogon.exe`, `csrss.exe`, `services.exe`, `svchost.exe`) plus the by-PID self-protection of the ALFRED process itself must never be weakened or bypassed — no new code path in `fechador.py` may close a process without first checking against this list (by exact name, never prefix/substring) and the running PID. Keep the self-protection check on `os.getpid()`, not on a process-name match against `python.exe`/`pythonw.exe` — a name-based check would also block unrelated Python processes that have nothing to do with ALFRED.
- `fechar_app` must keep trying `WM_CLOSE` (graceful) before `terminate()`/`kill()` (forced) — never skip straight to forced termination as a shortcut. The graceful attempt is what lets an app prompt "save before closing?" when it has unsaved work; only a genuinely unresponsive process (or one with no window at all) should ever reach the forced path.
