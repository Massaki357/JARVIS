# UI (janela principal, painéis, esfera animada, chat sobreposto)

> Contexto detalhado deste módulo, extraído do CLAUDE.md raiz. Leia antes de editar arquivos desta área.

## Arquitetura e decisões de design

1. **UI layer** — `jarvis/ui/janela_principal.py` (`MainWindow`, `QMainWindow`). Builds the PySide6 window (title, status label, call/analyze buttons, activity log) with an inline QSS stylesheet. Owns a single `GeminiLiveWorker` instance (`self.live_worker`), created fresh on each call and discarded when the call ends. All Gemini-thread signals (`status_recebido`, `erro_recebido`, `chamada_encerrada`, `solicitou_encerramento`, `nivel_audio`) are wired here.

   - **Console panel beside the activity log (`jarvis/ui/painel_console.py`)** — requested by the user after three rounds of freezes whose only diagnostic output went to a terminal nobody watches. The activity log shows what the assistant is *doing* (high-level status); this panel shows what is *happening underneath*: interruptions, watchdog warnings, connection failures, tracebacks. It **duplicates `sys.stdout`/`sys.stderr`** rather than being wired into each call site, so every existing `print` — `[INTERRUPÇÃO]`, `[VIGIA]`, `[CONEXÃO]`, `[MICROFONE]`, `[RESERVA]`, `[PRIORIDADE]`, plus anything a package prints and any traceback — shows up with no further changes. The original streams are never replaced, only echoed, so the terminal keeps working; `restaurar_saida_padrao()` runs in `closeEvent` so a late print can't write into a destroyed widget. Prints arrive from many threads (worker, MQTT listener, voice detector, package threads) and Qt widgets are GUI-thread-only, so writes cross through a `Signal` on an internal `QObject` with an explicit `QueuedConnection` — the same principle as `jarvis/nucleo/sinalizador.py`. Partial writes are buffered until a newline (a single `print` calls `write()` more than once), lines are timestamped and colour-coded by severity, and `document().setMaximumBlockCount(600)` caps growth so a diagnostic panel can never become the cause of the next freeze. Errors that reach the UI only as a `erro_recebido` Signal (never printed) are pushed in explicitly from `mostrar_erro`. The main window's minimum size went 560→900 wide, since two columns at 560px would leave both unreadable.
     - **Found while doing this: 13 of the 16 rules in `ESTILO_GLOBAL` are dead, and always have been.** The stylesheet comments its rules with `#`, but QSS has no `#` comment — only CSS-style block comments. A line starting with `#` parses as an id selector, and the real selector on the next line becomes its *descendant*, so the rule can never match. Proven empirically: the same `QTextEdit#console` rule applies when used alone and does **not** apply inside `ESTILO_GLOBAL`, and converting every `#` comment to a block comment makes all of them work. Only the 3 rules that happen to follow a blank line (e.g. `QPushButton#botaoChamada:hover`) were ever live — which is why the window renders in the system dark theme instead of the white/red design the code describes. **Not fixed here on purpose**: repairing it restyles the entire app to a light theme the user never asked for. The one-line fix is `re.sub(r"(?m)^#(.*)$", r"/* */", ESTILO_GLOBAL)`; it is the user's call. The console panel therefore styles **itself**, via `setStyleSheet` on its own widgets in `painel_console.py`, which is both better encapsulation and the only way its styling could work at all while the global sheet stays broken.
     - Also beware when writing QSS block comments: a `*/` inside the comment text closes it early and breaks the following rule. Hit exactly that while writing the comment explaining this very bug.
     - **Verified with 9 tests against a real `MainWindow`**: the panel exists with its opening line; a `print` from the main thread appears; a `print` from **another thread** arrives safely on the GUI; a `traceback.print_exc()` on stderr appears; a worker error delivered by Signal (never printed) appears; `sys.stdout` is confirmed *duplicated* rather than hijacked; 1200 lines of flood stay capped at the 600-line ceiling; the Limpar button empties it; and `restaurar_saida_padrao()` gives the real stdout back. The layout was also checked visually with a screenshot of the rendered window.

   - **Microphone/speaker selects on the main window (`jarvis/ui/painel_dispositivos.py`)** — two `QComboBox` above the activity log, one per direction. Logic lives in its own module; `janela_principal.py` only imports, instantiates and positions it, same approach as the console panel.
     - **The raw device list is unusable as-is**: Windows exposes the same physical device once per host API, and on this machine `sd.query_devices()` returns **46 entries** for about eight real devices. The panel groups duplicates and shows one row each — measured result here: 46 → **4 microphones and 4 speakers**. Grouping is by name prefix, because MME truncates names at 31 chars ("Microfone (HyperX Cloud Flight") while DirectSound gives the full one ("Microfone (HyperX Cloud Flight for PS)"); the longest variant is what gets displayed. `Windows WDM-KS` is hidden entirely (it re-lists everything with worse names — one real entry here was a driver path containing a newline, which would have broken the combo), as are the "Mapeador de som"/"Driver de som primário" pseudo-devices, since the explicit "Padrão do Windows" option already means exactly that. If filtering ever leaves the list empty, the unfiltered list is shown instead rather than an empty select.
     - **The index used comes from whichever host API PortAudio already treats as default on this machine** (MME here). The app always used that API implicitly, and audio is the fragile part of this project — switching the host API underneath as a side effect of adding a select would be changing two things at once.
     - **What is stored in `config.json` is the device NAME, never the index.** Indices shift whenever any device is plugged or unplugged, so storing one would silently point at the wrong microphone. On startup the name is resolved back to an index; a device that is no longer present falls back to the Windows default with a console warning instead of raising.
     - **Applied through `sd.default.device`**, which means every stream in the project picks it up with **zero changes**: the call's microphone, playback and the wake-word detector. `main.py` applies it before `ativacao_voz.iniciar()`, otherwise the first session would still open the old device.
     - Changing the microphone restarts the wake-word detector (`pausar()`/`retomar()`), since it holds the mic between calls and would otherwise keep the old device until the app restarted. A change during an active call only takes effect on the next one — an already-open stream cannot be repointed.
     - `preferencias.salvar_preferencia()` writes one key while preserving the rest of `config.json`, using the atomic `.tmp`-then-`replace` technique — a corrupted `config.json` would break app startup.
     - **Verified with 10 tests** against the real audio hardware: the list collapses correctly and contains no blank or newline-bearing names; both selects exist with "Padrão do Windows" first; choosing a device saves it and **preserves the other preferences** (`interrupcao` survived); `sd.default.device` receives the right pair; **real input and output streams actually open on the chosen devices**; the choice survives a simulated restart; a device name that no longer exists falls back to the default without raising; and returning to "Padrão do Windows" clears it. The user's real `config.json` was backed up and restored around the run.

   - **`VisualizadorAlfred` (`jarvis/ui/visualizador_alfred.py`)** — the animated sphere from `JARVIS COMPLETO` (`ui/alfred_visualizer.py`, class renamed to match this project's Portuguese convention). A self-contained `QWidget`: all the drawing (`QPainter`, background/sphere cached into `QPixmap`, adaptive FPS 6/15/20) lives inside it. The window uses exactly three methods: `definir_status(texto)` (called from the window's own `definir_status`, alongside the side label), `definir_ativo(bool)` (in `iniciar_chamada`/`chamada_finalizada`), and `definir_nivel_audio(float)` — connected to the worker's `nivel_audio` signal, which already existed and **had no listener at all before this**.
     - Layout: the window became three columns — controls + activity log (330px fixed), the sphere (all remaining space), and the diagnostic console (340px fixed). Minimum size went 900→1180 wide, default 1040×560→1380×760. Every panel that was already there (activity log, console, audio device selects) is still there — the user chose "esfera no centro, painéis atuais ao lado" over adopting the course's whole window. Verified by rendering the real window and screenshotting it.

   - **Translucent chat over the sphere (`jarvis/ui/painel_chat_sobreposto.py`)** — the assistant's spoken replies, in text, painted on top of `VisualizadorAlfred` without hiding the animation.
     - **The sphere is NOT OpenGL and NOT Qt Quick 3D**, and that single fact removes the whole class of problems this feature is usually expected to hit. `VisualizadorAlfred` is a plain `QWidget` whose `paintEvent` draws two cached `QPixmap`s with `QPainter`; the "3D" is a 2D illusion built from `QRadialGradient`. A grep for `QOpenGL|QtOpenGL|QQuick|QML|Qt3D|WA_NativeWindow|WA_PaintOnScreen` across the project returns **nothing**. So there is no native surface to compose against, no `WA_AlwaysStackOnTop` needed, and alpha blending just works: everything lands in the same backing store and Qt composites the non-opaque child over the parent on its own.
     - **The real trap is `QAbstractScrollArea`, not compositing.** `QTextEdit` paints its text area through its **viewport**, which stays opaque even when the widget's own stylesheet says `background: transparent` — the symptom is a solid rectangle sitting on the sphere. Both the widget and `viewport()` must be made transparent (`setAutoFillBackground(False)` + `WA_TranslucentBackground` on the viewport). A test asserts this directly, because it is invisible in code review and obvious only on screen.
     - **`WA_TranslucentBackground` is deliberately NOT set on the panel itself** — that attribute is for top-level windows. The translucent background is painted in `paintEvent` with an alpha `QColor`, and `WA_NoSystemBackground` is what lets the sphere show through underneath.
     - **It is a child of the sphere, outside every layout.** The sphere is the only widget in the main window with a stretch factor, so putting the chat in a layout beside it would steal the animation's space. It follows the parent's size through an **event filter installed on the parent**, so `visualizador_alfred.py` stays a pure drawing widget with no knowledge of the overlay. `janela_principal.py` (one of the three course files) only imports, instantiates and calls `limpar()` on call start — same footprint as `painel_console` / `painel_dispositivos`.
     - **Opacity lives in named constants** at the top of the module (`OPACIDADE_FUNDO` 0.55, `OPACIDADE_BORDA` 0.70, `OPACIDADE_TEXTO` 0.96), and `_com_alfa()` is the only place that turns a `jarvis/ui/estilo.py` token into an alpha colour — so there is exactly one place to tune how much of the sphere shows through.
     - **Measured cost: +0.34 to +0.42 ms per sphere frame**, against a 50 ms budget at `FPS_FALANDO` (20). A test fails if it ever exceeds a tenth of that budget. No flicker is possible — Qt double-buffers by default.
     - **The text arrives through `sinalizador.resposta_texto_recebida`**, the same signal the chat window already consumes, with an explicit `Qt.QueuedConnection` because all three workers emit it from their own thread. **This required closing a real gap**: only the Gemini and OpenAI workers emitted it — the local worker just printed and appended to the transcript, so the overlay would have stayed empty in exactly the mode where the response text had just become available (the MQTT `texto` user property). `_registrar_fala_do_assistente` now emits it too.
     - Shows the assistant only, not the user's own speech — the user asked for that and it reads fine, since you have just spoken and the sphere area stays uncluttered. The panel hides itself while empty and is cleared at the start of every call, so a new call never opens showing the previous conversation's answers.

## Restrições a preservar ao editar

- `painel_dispositivos` must keep storing the device **name** in `config.json` and resolving it to an index at load time — never store the index, which changes whenever any audio device is connected or removed. It must also keep applying the choice via `sd.default.device` rather than passing `device=` at each stream: that single assignment is what lets the call mic, playback and the wake-word detector all honour the selection without any of them being modified.
- The console panel must keep echoing `sys.stdout`/`sys.stderr` rather than being called from each print site, must keep crossing threads via its `Signal` (never touch the widget directly from a worker thread), and must keep its line cap — those three are what make it safe to leave on permanently. It must also keep styling itself in `painel_console.py`: a rule moved into `ESTILO_GLOBAL` dies silently, because of the `#`-comment bug documented above.
- **The chat overlay must stay a child of the sphere, outside every layout, and must keep its viewport transparent.** Putting it in a layout steals space from the only widget in the window with a stretch factor; letting `QTextEdit`'s viewport go back to opaque puts a solid rectangle over the animation (the widget's own `background: transparent` is not enough — it is a `QAbstractScrollArea`). Don't reach for `WA_TranslucentBackground` on the panel either: that is a top-level-window attribute, and the translucency here comes from painting an alpha colour in `paintEvent`. Keep the opacity in the named constants at the top of `painel_chat_sobreposto.py` rather than inlining alpha values, and keep the parent-following logic in the event filter so `visualizador_alfred.py` stays a pure drawing widget.
- **`_classe_do_worker()` in `jarvis/ui/janela_principal.py` stays the only place in the project that picks a voice brain**, and the three workers must keep exposing the identical public API (seven signals, the `(session_handle, transcricao_inicial, ativado_por_voz, slug_perfil)` constructor, `parar`, `solicitar_analise_tela`, `solicitar_analise_camera`, `enviar_texto_da_ui`, `enviar_imagem_da_ui`, `transcricao_conversa`, `slug_perfil`). A method the window calls on only one of them breaks the switch. The local worker's refusals must stay explicit (`erro_recebido` + `False`), never silent no-ops.
