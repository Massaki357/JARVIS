## Arquitetura e decisões de design

- `jarvis/pacotes/identificacao_planta/` — species identification from a camera photo via Pl@ntNet (`my-api.plantnet.org`), a botany-specialized API, used specifically because species ID isn't a general vision model's strong suit — this tool never touches the Gemini-based general camera analysis (`analisar_camera`), which is untouched and still the default for any other camera question. Same package contract as the others (`obter_function_declarations()`/`despachar()` — see **docs/INTEGRATION.md**), one no-parameter tool, `identificar_planta`.
     - **Request/response shape confirmed against the official docs before writing any code** (`my.plantnet.org/doc/api/identify` and the official example at `github.com/plantnet/my.plantnet/blob/master/examples/post/run.py`), not guessed: `POST https://my-api.plantnet.org/v2/identify/{project}?api-key=...`, image as multipart form field `images`, `organs` deliberately omitted (the docs confirm omitting it sets every image to `auto`-detection, which is the right default for a single unlabeled camera frame). `PROJETO_PLANTNET` defaults to `"all"` (broadest flora search) since the camera has no way to know the plant's region.
     - `plantnet_client.identificar()` returns up to `config.QUANTIDADE_RESULTADOS` (3) candidate species — scientific name, common name(s) if present, confidence score — in the order the API already returns them (descending confidence), never just the top match, specifically so the model can express "acho que é X, mas pode ser Y" instead of false certainty. `instrucao_sistema`'s `# IDENTIFICAÇÃO VISUAL ESPECIALIZADA` section tells the model to communicate uncertainty when the top score isn't clearly ahead of the second one — deliberately a system-prompt judgment call rather than a hardcoded numeric threshold in the tool response, since the model can weigh both the absolute percentage and the gap between candidates.
     - `_mensagem_erro()` gives a distinct message per known HTTP status (401 invalid/expired key, 404 no matching species, 429 daily quota exhausted), falling back to a generic message with whatever `message`/`error` field the JSON body has otherwise — never raises, matching every other package's `(sucesso, resultado)` convention.
     - **Verified against the real API, not just `py_compile`**: tested end-to-end (`plantnet_client.identificar()` and the full `despachar()` path) with a real `PLANTNET_API_KEY` and a real flower photo — correctly returned `Impatiens hawkeri` (New Guinea Impatiens) at 82% confidence as the top candidate, with two lower-confidence alternatives. Also confirmed the 401 (`"Bad token"`) error path with a deliberately invalid key.
